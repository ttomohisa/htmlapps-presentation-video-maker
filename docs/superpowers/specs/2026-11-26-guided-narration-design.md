# 発表者ノートからナレーション付きMP4を作る画面設計

2026-11-26 · v2.0.0（`594b71d`）を基準にしたSOL向け設計案

## 何を解決するか

「発表者ノートをまとめて読み上げる動画」を最優先とする。ノートのそろった資料を開いた人が、ヘルプを読んだり各スライドを回ったりせず、声を用意してMP4を保存できるのがゴール。作業途中で「3枚目だけ英語で」「表紙だけ自分で読む」と思ったときも、その場で変更できる。

公開版をWindows Chromeの1360 × 900とスマートフォン相当の390 × 844で操作した。ノート付き3枚のサンプルを読み込み、PCではテスト音声を各スライドに設定してMP4のダウンロードまで確認した。以下は画面観察に基づく判断で、初見の利用者による検証は実装時の受け入れ確認に含める。[観察対象の画面実装](https://github.com/ttomohisa/htmlapps-presentation-video-maker/blob/594b71d8bc08a28b1a5357ff98d73b55ac91c0aa/src/index.template.html)

| 現在の場面 | 何が起きているか | 新しい配置 |
| --- | --- | --- |
| ファイルを開いた直後 | デスクトップの工程案内は自動で閉じる。最初の画面で目立つ緑のボタンは「プロジェクトを保存」。スライドと台本は見えるが、次にどう音声を作るかが画面の下にある。 | 読み込み成功でナレーション画面に移り、資料名、ノートを取り込めた枚数、次の操作を先に出す。 |
| 自動で読ませたい | スライドの方式は「端末内読み上げ」が初期値。モデルの準備、選択中の1枚を生成、他のスライドの方式変更、一括生成が別々の操作になる。端末音声の「試聴」は動画に入らない。 | 新規資料の自動読み上げは資料単位で始める。モデルの準備を済ませたら1回で未作成分を生成できる。実際に動画で使う音声を聞ける。 |
| 書き出したい | PCの「録音素材」と「動画作成」、スマホの「動画」に録音と出力の役割が重なる。未録音時の案内も録音の完了を求める。 | 音声を用意する操作はナレーション画面、仕上げとMP4保存は動画画面。足りない音声から該当スライドへ戻れる。 |

全機能を一画面に置く編集方式なら、手作業の多い人は移動を減らせる。一方、今回の主経路では「今する操作」をファイルの有無、音声の有無、動画の有無で分けられる。そこで**「読み込み → ナレーション → 動画」の3画面**を採用する。利用者が指定したのは一括読み上げの優先。画面数、配置、以下の初期値は設計上の提案。

## 1　読み込み

ヘッダーには既存のアプリ名、表示言語、ヘルプ。本文は「PowerPointからナレーション付きMP4を作れます。」の下にファイルを置く場所と主ボタン **「PowerPointを開く」**。その下に小さく **「保存した作業を開く（.pvm）」**。大きなヒーロータイトル、空の編集欄、将来使う録音ボタンは置かない。最初に必要な制約は「.pptx、150 MBまで」。ファイル選択、ドロップ、キーボード操作の入口をそろえる。

読み込み中はファイル名と「スライドを読み込み中」。失敗時は理由と「別のファイルを選ぶ」を同じ場所に出す。成功した新規PPTXはナレーションへ。`.pvm` は全スライドの復元後に判定し、音声がすべて使用可能なら動画へ、それ以外はナレーションへ。再開時の選択スライドは維持する。資料を入れ替える操作は編集画面の「ファイル」にまとめ、現行データを破棄する前に確認する。

## 2　ナレーション

**起点は資料全体。** 例は発表者ノート付き3枚、ローカルモデルと日本語の声を選択済みのPC。角括弧は操作を表す。

```text
研修資料.pptx                                 [作業を保存]
読み込み  ›  ナレーション  ›  動画

発表者ノートを3枚分取り込みました
読み上げる言語  [日本語 ▾]        [音声の方法を変更]
音声があるスライド  0 / 3
[3枚分の音声を作る]                [1枚分を作って聞く]

スライド                       1　はじめに
 1  はじめに       音声なし      （スライドのプレビュー）
 2  進め方         音声なし      台本　発表者ノートから
 3  次のステップ   音声なし      本日は研修の進め方をご紹介します。…
                               [このスライドの設定]
```

- **PCで初めて使う人**には、対応環境で「ノートを読み上げる」を初期選択する。新規スライドの音声方式も同時に `local` にする。別途「全スライドに適用」を押す手順をなくす。日本語を初期値とし、英語（米国）を隣で選べる。UIの言語切り替えで台本の読み方を変えない。
- **ファイルがないとき**は、生成ボタンがある位置に「声の準備」を出す。共通モデル（約92 MB）と言語ごとの声（約522 kB）には別のダウンロードリンクを用意し、「モデルと声を選ぶ」から複数ファイルを選べる。既に持っている人は直接選べる。検証に通った各行を「選択済み」に変え、不足・不一致はファイル名と選び直し操作を表示。日本語と英語が混在する場合、一括生成対象が必要とする声を先にすべて示す。選択済みの正しいファイルは保持する。既存の配布先、ライセンス表示、検証を利用する。
- **ファイルがそろったとき**の主操作は「3枚分の音声を作る」。試聴は任意。選択中のスライドが有効なローカル音声を持つ場合は「スライド1の音声を聞く」と表示し、モデルを選んでいなくても再生できる。新しく試す場合は選択中の、動画に含める台本ありのローカルスライドを使う。選択行が別方式・空欄・除外なら、最初の未作成のローカル対象を提案する。「スライド2の音声を作って聞く」のように、実行前に対象番号を表示する。その1枚に必要なファイルだけでWAVを作り、そのスライドに保存して再生する。自動再生をブラウザが止めたら「音声を聞く」を出す。3枚中1枚を聞いた後の主ボタンは「残り2枚の音声を作る」になる。
- **ノートがないとき**は「3枚中1枚は、スライド本文を台本に使います」＋「台本を確認」。対象スライドへ直接移動する。本文も空の読み上げスライドは「台本なし・無音で含める」。含める／除外と音声の有無を分ける。手入力はいつでも可能。マイク・音声ファイルは台本が空でも音声を準備できる。
- **スライドの修正**は一覧の番号・見出し・音声状態から選ぶ。選択行とプレビューと編集欄には同じ番号を表示。台本は直接編集できる。原稿を戻す、方式・言語・速度、前後の間、動画に含める設定は各スライドに置く。録音やファイル差し替えもここで完結。「音声を作り直す」は該当する1枚にだけ効く。30枚のときは「音声の準備が必要なスライド」だけを絞り込める。
- **作業中**は主ボタンの位置で「音声を作成中　2 / 3枚（スライド4）」と「中止」を表示。中止・失敗時は完了枚数を残し「残りを作る」または該当スライドの「やり直す」に変える。資料全体の処理中も進捗と中止に戻れる。全対象がそろったら主操作は「動画の設定へ」。編集直後に自動で別画面へ飛ばさない。

モデルを持っていない人が最初に見る部分の例。準備が終わると同じ位置に枚数付きの生成ボタンが現れる。

```text
読み上げる言語   [日本語 ▾]
声の準備
  1. はじめて使うときは、この2つを保存します。
     [共通モデルをダウンロード · 92 MB]   [日本語の声をダウンロード · 522 kB]
  2. 保存したファイルをこのアプリで開きます。
     [モデルと声を選ぶ]
     共通モデル　選択済み     日本語の声　未選択
                                        [別の方法で音声を付ける]
```

### 音声の方法を選ぶ

| 表示名 | 選んだ後に出す操作 | 環境と対象 |
| --- | --- | --- |
| ノートを読み上げる | モデルと声を選ぶ → 音声を作る | 対象のPC版Chrome・Edge。日本語／英語。用意した音声はそのまま動画に使える。 |
| パソコンの声を録音する | 声を選ぶ → 読み上げを録音。音の確認は「声の見本を聞く」 | 端末のローカル音声と共有機能が必要。Windowsの確認済み経路では、実行直前に「画面全体」と「システム音声も共有」を案内。権限拒否・音声トラックなしでは選び直しと方式変更を表示。 |
| 自分の声を録音する | 録音する → 停止 → 録音を聞く | マイク権限は録音ボタンを押したときに要求。スマホの新規資料での初期選択。 |
| 音声ファイルを使う | このスライドの音声を選ぶ → 聞く・差し替える | PC・スマホ。既存の形式と上限を選択欄に表示。 |

新規資料の一括方式変更は対象枚数を明示し、準備済みの音声と個別に選んだ方式を保護する。資料全体と「このスライド」の設定を同名ボタンにしない。一括作成では、除外済み・無音・有効な生成済み音声・別方式のスライドを対象から外す。混在例でローカル2枚を作り終え、マイクの1枚が残れば、主操作は「スライド3を録音する」。処理が必要な方式が複数なら、不足分のうちスライド順で最初の対象に案内し、方式に応じて同じ作業をまとめる。

資料全体の方式を変えられる範囲は「含める・音声素材なし・資料の方式を継承」の3条件をすべて満たすスライド。「このスライドの設定」で方式を選んだら、その時点から個別指定とする。同じ方式をあえて選んだ場合も含む。「資料の方式に戻す」で継承に戻せる。新しい `.pvm` には既定方式とスライドの継承／個別指定を任意項目として保存し、従来どおり各スライドの実際の方式も書き込む。追加項目がないv1/v2を開いた場合は、復元した各スライドを個別指定として扱う。本人が継承に戻すまで、未録音のスライドも一括変更の対象にしない。ファイル形式のバージョンは維持する。

スマホでは自動読み上げで作成できると案内しない。主操作は「スライド1を録音する」、隣に「音声ファイルを使う」。端末内読み上げの見本は補助操作にする。PCで生成した音声入りの `.pvm` は、スマホでも音声を維持し動画に使える。画面幅の判定は配置用。狭いPCウィンドウでも利用可能なPC機能を維持する。

例えばPCで2枚作り、3枚目の音声がない `.pvm` をスマホで開いたら、「スライド3の声を選ぶ」へ案内する。ここで「このスライドを録音する」「音声ファイルを選ぶ」「PCで続ける」を選べる。方式を変更するのは利用者が選んだ1枚だけ。PCで続ける場合は `.pvm` の保存へ案内する。非対応のデスクトップブラウザも同じ扱い。新規資料の初期方式は、対象PCでモデルの生成に必要な機能（Worker、WebAssembly、DecompressionStream、Web Crypto）が使えればローカル、それ以外はマイク、マイク機能もなければ音声ファイル。権限を求めて可否を調べるのは利用者が録音を始めた時点とする。

## 3　動画

最初に「3枚・約42秒・1080p」のように完成物の見込みを表示し、その下にファイル名、解像度、主ボタン **「MP4を作る」**。字幕・BGM・切り替えは「仕上げの設定」、TXT／SRT／VTT・字幕プレビューは「台本・字幕を書き出す」に収める。タイムラインは含めるスライド順の確認に使う。新規資料は既存のPC 1080p／スマホ 720pを引き継ぎ、再開した資料は保存値を優先する。

音声がそろう前にもこの画面を開ける。その場合の主操作は「スライド2の音声を作る」など不足分へのリンク。対象0枚は「動画に含めるスライドを選ぶ」。すべて台本が空の読み上げ資料なら、既存仕様に合わせて「ナレーションなしで作成します」と表示し出力できる。

作成中は段階・進捗と「中止」。完成後は動画プレイヤーと **「MP4を保存」** を同じ場所に出す。「作業を保存（.pvm）」は二次操作。古いMP4があるときは「変更前の動画」と明記し、再作成の失敗や中止の後も再生・保存できる。新しいMP4への差し替えは成功した時点で行う。

## 画面共通の振る舞い

- PCの工程表示は現在地と移動先を兼ねる。スマホは同じ3項目を1つのナビで表示。読み込み前は入口だけを見せる。読み込み済みで「読み込み」へ戻っても資料は保持し、ファイル名・枚数と「ナレーションに戻る」を出す。資料名のそばに「作業を保存」。最初の保存時に「次回はこの.pvmを開くと続きを編集できます」と伝える。
- PCは上に資料全体の操作、その下を左に一覧・右に選択スライドと台本。スマホは上から現在地、次の操作、選択スライド、台本の1列。「スライドを選ぶ」で一覧を開く。プレビューは縦長画面で縮小・展開できる。初期表示で次の操作が見え、固定ナビが入力欄・進捗・中止ボタンを隠さない配置にする。
- 既存のヘッダーと緑を引き継ぎ、塗りつぶしボタンは現在の主要操作に使う。「シーン」は利用者向けには「スライド」に統一。ヘルプのスクロールは本文内に1本、スマホで「完全ローカル処理」バッジは非表示。説明文を増やすより、必要になった場所に具体的な操作名を出す。
- 工程変更時は見出しにフォーカス、一覧から修正先を開くときは対象の台本または録音操作へ。進捗は工程・対象枚数の変化を読み上げる。状態には文字を併記し、非表示画面にTabが入らないようにする。キーボード・200％拡大・日本語／英語で主操作を確認する。

表示用の状態は作業ファイルに保存する必要がない。音声エンジンは `src/local-tts-engine.js` とworkerに、動画処理は既存のエンコード経路に任せる。生成済みHTMLはビルド元にしない。設計段階ではリリース番号を決めない。

### 受け入れ確認

1. 初見の人にノート付き3枚の資料と「ナレーション付きMP4を保存してください」だけを渡す。ヘルプを開かず、台本を3回確認せずに、ファイル準備からMP4保存まで到達できるか観察する。「声の見本」「動画に入る音声」「作業を保存」のどれで迷ったかを記録する。
2. 実モデルで日本語2枚と英語1枚。声が一部不足したときは対象言語を示す。1枚を生成・試聴してから残りを生成すると、先のWAVを維持する。中止して再開しても完了済みを飛ばす。原稿を1枚だけ直すと、その1枚だけが要更新になる。
3. ノートなし・本文あり、本文も空、除外、マイク、音声ファイルが同じ資料にある場合。表示件数と出力内容が一致する。スマホ相当では録音／ファイル、狭幅PCではローカル読み上げを選べる。権限拒否でも別方式で続けられる。2枚生成済み・1枚未作成のPCプロジェクトをスマホで開き、既存の2枚を残して3枚目だけ音声ファイルで完成できる。
4. v1/v2の `.pvm` を開き、台本・音声・スライドの個別設定・BGM・出力設定を確認する。新規保存では音声方式の個別指定が再開後も保たれ、旧ファイルの未録音スライドも一括変更で書き換わらない。音声のそろった資料はオフラインでMP4を作れる。生成済みの1枚はモデル未選択でも聞ける。原稿を直して再生成を中止しても、以前のWAVは作業ファイルに残り、同じセッションで作成済みのMP4は「変更前の動画」として保存できる。
5. 30枚の資料、320px幅、600px前後、PC画面で、選択スライド・主操作・中止が見つかる。言語を切り替え、Tab、Enter、Escで操作できる。ページに横スクロールが生じない。
6. `node --test tests/*.test.cjs` と `scripts/check-repository.ps1` を実行。ブラウザで音声入りMP4の再生と保存を確認し、既存の途切れ対策も検証する。公開版相当と `file://` の両方で動作し、ローカル資料や音声を送信しない。
